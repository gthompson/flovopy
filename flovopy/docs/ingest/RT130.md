# REF TEK RT130 — CF cards → `rt2ms` → SDS

[Index](README.md) · [Quick start](Quick-Start.md) · [CLI](Configuration-and-CLI.md) · [StationXML](StationXML.md) · [QC](Validation-and-QC.md) · [SDS merging](SDS-Merging.md)

**Source:** EarthScope EPIC *RT130 Data Processing (rt2ms 2021.090 and later)*, revised 12 August 2025. This procedure requires PASSOFT `rt2ms`; FLOVOpy does **not** decode REF TEK CF-card packets directly.

## Step 1 — Preserve original CF-card data

Place each copied CF card under a `RAW/*.cf` directory in a dedicated conversion workspace, for example `/data/SVC1/10_conversion/RT130/RAW/`. Follow the EPIC drag-and-drop procedure and keep an unchanged original copy. `rt2ms` writes `MSEED/`, `LOGS/`, `rt2ms.msg` in its workspace.

## Step 2 — Explore and review the parfile

```bash
python -m flovopy.ingest.cli rt130 explore /data/SVC1/10_conversion/RT130
python -m flovopy.ingest.cli rt130 explore /data/SVC1/10_conversion/RT130 --execute
```

With multiple `RAW/*.cf` folders the wrapper creates `dir.list` and invokes `rt2ms -D dir.list -e`; for a single RAW tree without `*.cf` children it uses `rt2ms -d RAW -e`. The generated `parfile.txt` contains **time-dependent** assignments. Review `das; refchan; refstrm; netcode; station; location; channel; samplerate; gain; implement_time`. Correct only the fields EPIC permits (typically network, station, location, channel); keep acquisition parameters intact. Account for equipment changes. `XX` is a placeholder network code, not a final deployment assignment.

## Step 3 — Convert to daily MiniSEED

```bash
python -m flovopy.ingest.cli rt130 convert /data/SVC1/10_conversion/RT130
python -m flovopy.ingest.cli rt130 convert /data/SVC1/10_conversion/RT130 --execute
```

The wrapper checks parfile syntax and unresolved network/station/channel fields, then calls `rt2ms -D dir.list -p parfile.txt` or the single-directory equivalent. Inspect `rt2ms.msg` and `LOGS/`: individual bad packets may be skipped while conversion continues. Outputs are EPIC daily MiniSEED files named `STA.NET.LOC.CHAN.YEAR.DOY` (often **without an extension**).

## Step 4 — Optional SOH-only diagnostics

```bash
python -m flovopy.ingest.cli rt130 logs /data/SVC1/10_conversion/RT130 --execute
```

Uses `rt2ms -X` and produces logs for `sohviewer`/`logpeek`. Do not assume that `LOGS/` text is MiniSEED waveform data.

## Step 5 — Stage to SDS and merge

```bash
python -m flovopy.ingest.cli rt130 stage \
  /data/SVC1/10_conversion/RT130/MSEED \
  /data/SVC1/20_archive/RT130/SDS
python -m flovopy.ingest.cli rt130 stage \
  /data/SVC1/10_conversion/RT130/MSEED \
  /data/SVC1/20_archive/RT130/SDS --execute
```

The `stage` operation handles extensionless RT130 day-volume names, using the shared daily staging engine. Review station/channel names, packet timing, GPS warnings and any `rt2ms` error messages before [merging](SDS-Merging.md).

## Step 6 — Metadata and EPIC delivery

Create **experiment-wide StationXML with Nexus**, including the time-dependent deployment history. [StationXML guide](StationXML.md). For EPIC submission, check headers/byte order, [QC](Validation-and-QC.md), and use the approved daily volumes with `data2passcal` after contacting EPIC. [EPIC workflow](EPIC.md).

**Limitations:** This wrapper has not been validated with real RT130 CF-card data; the installed PASSOFT version, card layouts and `rt2ms` output must be checked locally.
